### VK Crypto

###### Расширение для реально **безопасного** общения в ВК в Chromium-браузерах.

Версия: 0.0

Обновлено: 04.05.2026

###### 

##### Установка и первая настройка

1. Скачайте zip-архив из github (зеленая кнопка Code) или склонируйте репозиторий любым доступным образом.

   * Распакуйте этот zip-архив в любую удобную папку
2. Зайдите на chrome://extensions и нажмите "Загрузить распакованное расширение" выбрав папку расширения.

   * Для того, чтобы эт кнопка появилась нужно включить "Режим разработчика"
   * Нужно выбирать папку, где лежат файлы, например этот, README.md
   * В других Chromium-based браузерах chrome замените на название браузера. Например edge, opera, brave, browser.
3. Сгенерируйте свой первый RSA-ключ. Для этого, нажмите на "Сгенерировать" в всплывающем окне.

   * Его можно открыть нажав на расширение в списке расширений около поисковой строки (в Chrome).
   * У вас отобразится часть открытого ключа. Его **можно и нужно** рассказывать другим людям. Закрытый ключ хранится локально в Chrome. Сайты и другие расширения не имеют к нему доступа. *(TODO: сделать систему с паролем для ~~параноиков~~ тех, кто заботится о безопасности больше остальных)*.



##### Использование

В этом разделе написано о том, как пользоваться расширением для повседневной отправки сообщений в одном из немногих *безопасных* месснджеров, которые ловят даже на парковке.

1. Вы должны получить **открытый** ключ адресата и вставить его в специальное меню.

   * Меню можно открыть по нажатию на синюю кнопку "Crypto" (предложите название лучше) в чате с человеком. Она находится около кнопки звонка.
   * Вставьте полученный ключ и нажмите "Обновить".
   * Важно: ключ должен быть получен из надежного *(но не обязательно секретного)* источника. Иначе, возможны атаки человека посередине.
   * У адресата тоже должен быть ваш ключ. Однако, это требуется только для того, чтобы работали подписи. *(TODO: добавить возможность менее безопасных сообщений без подписей)*.
2. Пишите ваше сообщение в поле для его ввода как обычно.

   * На текущий момент, создателем расширения не было получено доказательств о том, что VK читает и логирует все нажатия кнопок.
   * *TODO: Добавить возможность написания на странице расширения и отправки уже пакета в мессенджер. Для особо важных сообщений.*
3. Отправьте по нажатию Alt-Enter (Command-Enter на MacOs). Это отправит зашифрованный пакет-строку.

   * Если при отправке пакет превысит 4096 символов (лимит текста вк) будет показана ошибка. *(TODO: решить это)*.

   * *TODO: Добавить возможность изменения/добавления кейбинда.*
4. Все текстовые сообщения автоматически расшифровываются расширением используя Ваш приватный RSA-ключ.

   * На текущий момент, на одного человека хранится один открытый ключ. *(TODO: Сделать хранения целого списка ключей.)*

##### Как это работает

Если вы открыли этот раздел, то я очень рад, что хоть кому-то интересно как это работает и я это писал не зря.

* У каждого пользователя есть PUB\_RSA, PRIV\_RSA (в коде называется не так, это для простоты здесь написано так). Пусть отправитель - А, его ключи PUB\_RSA\_A, PRIV\_RSA\_A; получатель - B.
* Расширение использует алгоритмы RSA-OAEP и AES-GCM для шифрования и RSA-PSS для подписей.

  * Размер RSA - 2048 битов, AES - 256, везде используется хеш SHA-256.
  * Про конкретно работу этих алгоритмов читайте на википедии.
* При отправке использутся также PUB\_RSA\_B, IV - параметр AES и сам ключ для AES - так и назовем, AES.
* Пакет содержит следующие поля

  1. version - версия расширения. Скорее всего будет реализована какая-то обратная совместимость для старых пакетов.
  2. key\_sender - RSA\_ENCRYPT(AES, PUB\_RSA\_A) - требуется, чтобы сам отправитель мог читать свои же сообщения.
  3. key\_recipient - RSA\_ENCRYPT(AES, PUB\_RSA\_B) - чтобы получатель мог получить AES-ключ для расшифровки сообщения. *Фактически, все кто могут расшифровать хотя бы один из этих ключей могут прочитать сообщение.*
  4. iv - IV. Его можно передавать, это не ломает криптографическую стойкость.
  5. ciphertext - AES\_ENCRYPT(TEXT, AES) - это и есть зашифрованное AES'ом сообщение. Так как AES - симметричный алгоритм, то расшифровать его можно тем же самым AES-ключом, что и зашифровали.
  6. signature - RSA\_PSS\_SIGN(PRIV\_RSA\_A, SHA256(packet\_without\_signature)) - та самая подпись. **Это использует, но не раскрывает ваш PRIV\_RSA\_A.** Это нужно, чтобы:

     1. Расширение могло понимать чье это сообщение (ваше или собеседника).
     2. Злоумышленник не мог написать сообщение от имени друга без его приватного ключа. Остальное как можно заметить не требует PRIV\_RSA\_A.
* Для безопасности, везде при шифровании добавляется случайная "соль".
* Вся криптография реализована встроенным в браузер CryptoJS. Спасибо разработчикам языка и Chromium.
* **Если вы разбираетесь в теме (я - нет) и нашли важные недочеты в безопасности алгоритма - напишите Issue.**
